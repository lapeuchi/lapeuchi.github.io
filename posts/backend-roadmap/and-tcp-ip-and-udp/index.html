개요

프로토콜 관련해서 TCP/IP라는걸 정말 많이 들어봤을 것이다. TCP와 IP를 합쳐서 TCP/IP라고 많이 하는데 TCP, IP 두 프로토콜에 대해 알아보고 왜 둘을 붙여서 부르는지도 알아보자.

그리고 안정적인 TCP 대신 가끔씩 속도가 생명인 컨텐츠에서 쓰이는 UDP, 그리고 TCP와의 차이도 같이 알아보도록하자.

IP(Internet Protocol)

비연결의 서비스를 제공하며, 발신지와 목적지까지의 라우팅 경로를 설정한다.

IP는 패킷을 최대한 빠르게, 정확한 목적지로 보내는 프로토콜이다.

패킷 전달 여부를 보증하지 않고, 패킷을 보낸 순서와 받는 순서가 다를 수 있다.

TCP (Transmission Control Protocol)

TCP는 패킷이 손실되지 않고, 순서대로 잘 도착하도록 확인하는 프로토콜이다.

손실없이 차례대로 보내기 때문에 전송속도는 느리다.

패킷이 도착했을 때 패킷이 손실되거나 손상되어 있으면 출발지에 재전송해달라는 요청을 한다.

TCP의 3 way handshake

TCP는 데이터를 상대방에게 확실하게 보내기 위해서 3 way 핸드쉐이킹이라는 방법을 사용하고 있다. 이 방법은 패킷을 보내고 잘 보내졌는지 여부를 상대에게 확인하러 간다.

본격적인 상대 클라이언트와 연결되기 전, 가상 연결을 하여 패킷을 보내 확인하는 동작이다.

아래는 3 way handshake에서 동작 과정 중 사용하는 패킷이다.

  • SYN: 연결을 생성할 때 클라이언트가 서버에 시퀀스 번호를 보내닌 패킷 (접속 요청)
  • SYN-ACK: 시퀀스 번호를 받은 서버가 ACK 값을 생성하여 클라이언트에게 응답하는 패킷
  • ACK: ACK 값을 사용하여 응답하는 패킷 (요청 수락)

3 way handshake의 동작 과정

  1. 클라이언트 -> 서버: SYN 패킷 전송
  2. 서버 -> 클라이언트: SYN + ACK 패킷 전송
  3. 클라이언트 -> 서버: ACK + 데이터 패킷 전송
  4. 데이터 패킷 전송

TCP가 패킷 순서를 보장하는 방법

TCP가 패킷 순서를 제어할 수 있는 이유는 TCP 데이터 안에 전송 제어, 순서 같이 정보들이 있기 때문에 가능한 것이다.

아래는 패킷1, 패킷2, 패킷3을 각각 차례대로 전송해야 하는 상황에서 서버에서 순서를 꼬이게 받았을 때 예시 상황이다.

  1. 클라이언트에서 패킷1, 패킷2, 패킷3 순서로 전송
  2. 서버에서 패킷1, 패킷3, 패킷2 순서로 받음
  3. 서버에서 패킷2 부터 다시 보내라고 클라이언트에게 요청

UDP (User Datagram Protocol, 사용자 데이터그램 프로토콜)

TCP의 반대라고 생각하면 쉽다. TCP는 ‘꼼꼼함’이 특징이라면 UDP는 ‘대충 빨리’같은 느낌이 특징이다.

비 연결지향적에 패킷 순서 보장이 안된다. 하지만 TCP에 비해 전송이 빠르다.

TCP에 비교해서 기능이 거의 없어 단순하고
IP에서 PORT와 체크섬(메시지 검증해주는 데이터) 정도만 추가된 형태라고 생각하면 된다.
IP에 기능이 거의 추가되지 않은 하얀 도화지 같은 상태이기 때문에 최적화 및 커스터마이징이 용이하다.

TCP와 UDP의 차이

구분TCPUDP
연결 방식연결지향형 프로토콜비 연결지향형 프로토콜
데이터 전송 방식바이트 스트림 기반 연결메세지 스트림 기반 연결
제어 기능혼잡제어, 흐름제어 지원혼잡제어, 흐름제어 없음
순서 보장전송 순서 보장, 상대적으로 느림순서 보장 없음, 상대적으로 빠름
신뢰성신뢰성 있는 데이터 전송 (안정적)데이터 전송 보장 없음
데이터 단위세그먼트 (TCP 패킷)데이터그램 (UDP 패킷)
활용 예시HTTP, Email, 파일 전송실시간 게임 서버, DNS, 실시간 스트리밍 서비스

TCP/IP

TCP와 IP는 대부분의 인터넷 기반 응용 프로그램 및 서비스에서 사용되는 기본 통신 프로토콜이다.

TCP와 IP를 하나로 묶어서 얘기하는 이유는 위에서 이야기 했듯 기본적으로 둘의 조합을 많이 사용하기 때문이다.

패킷을 보낼 때 IP를 사용하여 최대한 빨리 패킷을 전송하고 TCP를 활용해서 패킷을 안전하게 수신받는다.

TCP/IP 처럼 복수의 프로토콜 집합을 프로토콜 스택(Protocol Stack) 혹은 프로토콜 스위트(Protocol Suite)라고 한다.
