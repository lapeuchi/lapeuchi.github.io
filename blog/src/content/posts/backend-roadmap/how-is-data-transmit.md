## 데이터가 송수신되는 과정

![이미지](https://westahn.com/wp-content/uploads/2024/02/OSI7OSI4.png)

위 이미지를 기준으로 설명하겠다.

OSI 7 계층과 TCP/IP4 계층은 데이터가 인터넷을 통해 어떻게 전달되는지 보여주는 모델이다.

두 모델 사이에 있는건 각 계층에서 사용하는 프로토콜이다.

데이터를 보내는 입장은 제일 아래 계층에서, 받는 입장은 제일 위 계층에서부터 시작한다는 것을 알고 있으면 좋다.

## OSI 7 계층 (OSI 7 Layers)
OSI 7계층은 국제표준화기구(ISO)에서 데이터가 송수신되는 과정을 7개의 계층으로 나누어 정리한 것이다.   
OSI 7 Layers가 현실에서 일어나는 네트워킹과는 완전히 대응되지 않지만, 프로토콜이나 기술들의 기반이 되기도 한다.

각 계층을 설명하기 전 다음과 같은 용어를 숙지해야 한다.

* 노드(Node): 네트워크 상의 장치나 시스템을 의미하며, 데이터가 통신하는 과정에서 거치게 되는 각 지점 또는 컴퓨터 자체를 가리킨다. 즉, 네트워크를 구성하는 라우터, 스위치, 서버, 또는 PC 등 통신에 참여하는 모든 컴퓨터나 장치들이다.

* 호스트(Host): 통신 데이터의 최종 목적지 또는 출발지인 최종 사용자 장치 자체

### 1. 물리 계층(Physical Layer)  
* 데이터를 비트 단위의 전기신호로 만들어 송수신한다. 오로지 데이터를 전달하는 목적을 가지고 어떤 데이터인지, 어떤 에러가 있는지 등에 대해서는 관여하지 않는다.  
* 전송 단위: 비트 (bit)  
* 장비: 통신 케이블, 리피터, 허브 (전기적 신호가 나가는 물리적인 장비를 사용한다.)

### 2. 데이터링크 계층(Data Link Layer)  
* 물리 계층을 통해 송수신되는 정보의 오류와 흐름을 관리하여 안전한 정보 전달을 수행할 수 있도록 도와주는 역할을 한다.  
통신에서의 오류를 찾고 재전송한다.  
* 패킷이 도착했을 때 MAC 주소를 통해 host에게 전달한다.  
* 흐름 제어 : 송신 측과 수신 측의 속도 차이를 조정  
* 오류 제어 : 오류 검출과 회복  
* 순서 제어 : 프레임의 순서적 전송  
* 프레임 동기화 : 프레임의 시작과 끝을 구별하기 위한 동기화  
* 전송 단위: 프레임 (frame)  
* 장비: 브릿지, 스위치, 이더넷 

### 3. 네트워크 계층 (Network Layer)  
* **경로와 주소를 정하고 패킷을 전달한다.**  
* 최적의 경로를 설정하여 목적지까지 가장 안전하고 빠르게 보내는 기능이 있다. (라우팅 기능)  
* 서로 다른 네트워크에 위치하는 host 간에 데이터를 주고 받을 때 작동하며 각 장치를 고유하게 식별할 수 있게 하는 Logical addressing과 같은 처리를 담당한다.  
* 전송 단위: 패킷 (packet)

### 4. 전송 계층 (Transport Layer)  
* 양 끝단 사용자들 간의 신뢰성있는 데이터를 주고 받게 해준다. (완전한 메세지(complete message)를 end-to-end로 전달하는 역할)  
* 데이터 전송이 성공적으로 완료되었는지 확인하고, error가 발견되면 데이터를 다시 보내는(re-transmit) 역할을 한다. (오류검출 및 *(복구, 흐름제어, 중복검사 등) 
* 전송 단위: 세그먼트 (segment)  
* 대표적인 프로토콜: TCP, UDP

### 5. 세션 계층 (Session Layer)  
* 응용 프로세스가 통신을 관리하기 위한 방법을 정의한다.  
* TCP/IP 세션을 만들고 없애는 역할을 한다.  
* connection(연결) 유지, session의 유지 및 인증, 보안을 담당한다.

### 6. 표현 계층 (Presentation Layer 혹은 Translation Layer)  
* 전송하는 데이터의 표현방식을 결정한다. ex) 데이터변환, 압축, 암호화 등 / GIF, JPEG, ASCII 등 
* 송신자에서 온 데이터를 해석하기 위한 응용계층 데이터 부호화, 변화  
* 수신자에서 데이터의 압축을 풀수 있는 방식으로 된 데이터 압축  
* 데이터의 암호화와 복호화  
* 응용 계층의 데이터를 네트워크에 전송하기 위해 요구되는 format으로 조작한다.

### 7. 응용계층 (Application Layer)  
* 사용자와 가장 가까운 계층, 우리가 사용하는 응용 프로세스나 서비스가 동작하는 계층이다.  
* 최상위 계층으로서, 사용자/어플리케이션이 네트워크에 접속할 수 있게 해주는 계층이다.  
* end system이 이메일과 같은 서비스를 제공받기 위해 어떤 형식으로 메세지를 주고 받아야하는지에 대한 프로토콜이 모여 있는 레이어이다.  
* socket이나 port number가 이 레이어와 관련이 되어 있는 지식이다.  
* 대표적인 프로토콜: HTTP, FTP

## TCP/IP 4 계층
인터넷의 전신인 아파넷에서 TCP/IP 프로토콜을 처음 사용하면서 등장한 모델이다.  
기존의 OSI 7계층은 데이터 통신에 필요한 계층과 역할을 정확하게 정의하려고 한 모델이다. 단계가 많고 구조가 복잡해서 간단하면서 인터넷 서비스에 적합한 TCP/IP 4 계층 모델이 생겨났다고 한다.  
TCP/IP는 지금 현존하는 대다수의 프로그램이나 서비스에서 사용되는 프로토콜이다.  
TCP/IP 4계층은 현재 인터넷에서 사용되는, 좀 더 실무적이면서 프로토콜 중심으로 단순화된 모델이라고 볼 수 있다.

현재 OSI 7 Layers 보다 많이 활용되는 모델이라고 한다. (이론보다는 실용적인 느낌)

### 1. 네트워크 엑세스 계층 (Network Access Layer)
1. 알맞은 기기로 데이터가 전달되도록 MAC주소를 핸들링하고, 데이터 패킷을 전기신호로 변환하여 선로를 통해 전달할 수 있게 준비한다.
2. OSI 7 계층에서 물리, 데이터링크 계층의 역할을 한다.

### 2. 인터넷 계층 (Internet Layer)
1. IP를 담당하는 계층
2. IP를 사용하여 데이터의 시작지와 목적지에 관한 데이터를 첨부한다.
3. OSI 7 계층에서 네트워크 계층의 역할을한다.

| Protocol | Content |
|----------|---------|
| **IP**   | 비연결의 서비스를 제공하며, 발신지와 목적지까지의 라우팅 경로를 결정 |
| **ICMP** | IP 제어와 메시지 기능을 담당 |
| **ARP**  | IP 주소를 이용해 상대방의 MAC 주소를 알아오는 프로토콜 (브로드캐스트 요청, 유니캐스트 응답) |
| **RARP** | MAC 주소에 해당하는 IP 주소를 알아오는 프로토콜 (브로드캐스트 요청, 유니캐스트 응답) |

### 3. 전송계층 (Transprot Layer)
1. TCP / UDP를 담당하는 계층
2. OSI 7 계층에서 전송계층에 해당한다.

| Protocol | Content |
|----------|---------|
| **TCP (Transmission Control Protocol)** | 연결 지향적 (Connection Oriented)<br>신뢰적, 흐름제어, 에러 제어 (순서번호, ACK 번호 사용)<br>ACK 받지 못한 모든 데이터는 재전송<br>✅ 장점: 보장된 세그먼트 전달 → 신뢰성 높음<br>⚠️ 단점: 연결을 위한 초기 설정 시간이 걸림 |
| **UDP (User Datagram Protocol)** | 비연결 지향적 (Connectionless Oriented)<br>비신뢰적, 데이터를 보낸 후 도착 여부 검사 기능 없음<br>✅ 장점: 빠르고, 연결 설정/제어 프레임 불필요 → 네트워크 부하 감소<br>⚠️ 단점: 신뢰성 부족, 주로 고속성이 필요한 멀티미디어 응용에서 사용됨 |

### 4. 응용 계층 (Application Layer)
1. HTTP / FTP를 담당하는 계층
2. 서버나 클라이언트(웹 브라우저 등) 응용 프로그램이 이 계층에서 동작한다.
3. OSI 7 계층에서 세션, 표현, 응용 계층에 해당한다.

| Protocol | Content |
|----------|---------|
| **DNS (Domain Name System)** | 인터넷에서 사용하는 이름을 해당 IP 주소로 변환해주는 서비스 |
| **SNMP (Simple Network Management Protocol)** | 네트워크 장비를 모니터링하고 제어하는 프로토콜 |
| **FTP (File Transfer Protocol)** | TCP 환경에서 파일 전송을 지원하는 프로토콜 |
| **TFTP (Trivial File Transfer Protocol)** | UDP 환경에서 파일 전송을 지원하는 프로토콜 |
| **HTTP (Hypertext Transfer Protocol)** | 웹상에서 정보를 주고받을 수 있는 프로토콜 |
