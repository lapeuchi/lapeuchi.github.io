# 절차지향 & 객체지향

## 절차지향

- 작은 프로그램을 만들 때 효율적
- 좀 복잡해지면 코드 수정이 힘듬
- 심플함 & 직관적
- 함수 기반, 위에서 아레로 흐르는 순차적인 처리, 프로그램 전체가 유기적으로 연결됨
- 프로그램이 비대해지고 복잡해질수록 유지 보수가 힘들고 로직이 꼬일 수 있음

## 객체지향

- 모든걸 객체위주로 생각함
- 객체 (OOP Object Oriented Programming) :
    - 코드 내의 모든 것 ex)  플레이어, 몬스터, 화살, + 게임속에 존재하는 모든 것이 다 객체이다.)
- class : 객체를 묘사할 때 사용
- public : 선언된 클래스 외부에서도 사용가능
- private : 선언된 클래스 안에서만 사용가능
- new : 객체를 새로 생생할 때 사용한다.

[class 구조](class%20%E1%84%80%E1%85%AE%E1%84%8C%E1%85%A9%20e84f22d3bb484ea6ad35daebb2206441.md)

```csharp
class Knight
{
		//knight라는 객체의 설계도라고 봐도 됨 (기사맛 붕어빵 틀)
		public int hp;
		public int attack;
		//class에서 변수를 선언하는 곳을 field라고 한다

		public void Move()
		{
				Console.WriteLine("Move");
		}
		public void Attack()
		{
				Console.WriteLine("Attack");
		}
		//field 아레는 메소드를 정의한다.
}

class Program
{
		static void Main(string[] args)
		{
				Knight knight = new Knight;
				//Knight knight = null;  
				//존재하지 않는 객체로 선언 (오류남)
			

				//객체를 새로 만들 때 new를 사용한다.
				//붕어빵이 틀에서 만들어짐
				//new가 없으면 변수가 할당되지 않아 오류가 남

				knight.hp = 100;
				knight.attack = 10;
				knight.Move();
				knight.Attack();
		}
}
```
